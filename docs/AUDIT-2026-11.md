# Security, permissions and privacy check (21 Nov 2026)

## Android (Play build: `PLAY=1`)
- Permissions: only `RECORD_AUDIO` (asked when Record lesson is tapped). No INTERNET, no camera, no storage, no location.
- `allowBackup=false`, `usesCleartextTraffic=false`; one exported activity (the launcher).
- WebView: file access off; every request to a host other than the app's own is refused (403); microphone granted only to the app's own page; the camera is never granted.
- Links from a page open in the browser only for http/https (**fixed in this check**: any scheme could be passed to Android before).
- JS bridge: `saveFile` (writes to Downloads/Teachly through MediaStore, no permission), `saveBegin` / `saveChunk` / `saveEnd` (the same, for a big file such as a long lesson video, sent in pieces through a temporary file in the app's cache, deleted after saving) and `version` (now 2); reachable only from the app's own page.
- targetSdk 36, minSdk 24; Android 13+ back callback; notch kept clear.

## Web
- CSP on every page: scripts only from the app itself, no frames, no objects.
- No outside requests (fonts and code are bundled; e2e `no-external` checks it).
- User text reaches HTML only escaped; the save-status message is now set as text (**fixed**: a browser error message went in as HTML).
- Dependencies: `dompurify` updated to 3.4.18 (**fixed**). Left: `echarts`/`uuid` inside `pptx-preview` (moderate; fixing needs a breaking pptx-preview update). Risk is low: echarts draws charts of a PowerPoint the teacher opens, and the CSP blocks inline scripts.
- pdf.js 6.4 (well past the 2024 font-eval issue).

## Secrets
- No key, password or token in the repo or its history. The upload key lives in GitHub Secrets; the Build for Play workflow runs only on `main`, only for the repo owner; its actions are pinned to exact commits (**changed in this check**, also removes the Node 20 / setup-java deprecation warnings).

## Privacy policy and Terms (`src/ui/legal.ts`)
- Checked against the app: they match (no data collected; microphone only for recording; Play build without internet; website host logs; data only on the device). Nothing changed in what is stored, sent or which permission is used, so the date stays 20 November 2026.
- Not legal advice: a lawyer should still review them (company details, governing law, the contact address).

## For the owner (cannot be done from the code)
- Google Play needs the privacy policy at a public URL on physica.in (not the GitHub address, which shows the account name).
- The website runs at the GitHub Pages address, which shows the GitHub account name; a custom domain (for example teachly.physica.in) would hide it.

## Update 22 Nov 2026: long recordings
- A lesson video is now written to the device (IndexedDB, keys rec:*) piece by piece while recording, so a 2-hour lesson never fills the memory; the pieces are deleted about 10 minutes after the video is saved, or when an unfinished recording is deleted. A recording cut off by the app closing can be saved next time.
- This changes what is stored, so the privacy policy (section 1) and its date (22 November 2026) were updated in the same change. Nothing is sent anywhere; no new permission.
